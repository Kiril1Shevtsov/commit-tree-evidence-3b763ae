## Проверка без доступа к закрытым материалам

Нужен Python 3.9 или новее, без сторонних библиотек. Скачайте весь репозиторий через **Code → Download ZIP** и распакуйте внешнюю загрузку, сохранив структуру каталогов. Исследовательский ZIP внутри `evidence/` оставьте неизменным.

Альтернатива через Git без преобразования переводов строк:

```sh
git -c core.autocrlf=false clone https://github.com/Kiril1Shevtsov/commit-tree-evidence-3b763ae.git
cd commit-tree-evidence-3b763ae
```

Запустите из корня скачанного набора:

```sh
python3 -B verify.py --check-sums
python3 -B -O verify.py --check-sums
```

Успех: JSON с `"status": "PASS"`, код завершения 0. Ошибка даёт ненулевой код. Скрипт не использует сеть, не извлекает архив на диск и не запускает содержащиеся в нём программы.

Проверяется вся цепочка:

- RSA-4096 / PKCS#1 v1.5 / SHA-256 подпись точного commit с закреплённым ключом.
- Git IDs commit, root tree и manifest с учётом типа, длины и точных байтов объекта.
- Ссылка на tree в подписанном commit и ссылка на manifest в root tree.
- Запись выбранного архива в manifest: имя, размер, SHA-256 и записанные транспортные поля.
- Размер и SHA-256 фактически опубликованного ZIP.
- CRC, размеры, уникальность и безопасность имён всех 247 файлов ZIP.
- Все 246 записей размеров и SHA-256 во внутреннем верхнем manifest архива, включая 131 документ. Сам внутренний manifest охвачен SHA-256 всего ZIP.

Проверка не требует внешнего транспортного тома PART_003: связь с опубликованным внутренним ZIP проверяется по его SHA-256 в точном подписанно-связанном manifest. Записанные транспортные поля проверяются как данные manifest; сам внешний том в этот набор не входит.

`SHA256SUMS` дополнительно позволяет обнаружить изменение опубликованных файлов. Он не является независимым удостоверением программы проверки. Код `verify.py` и его константы доступны для изучения.

## Границы проверки

Проверка устанавливает подпись и связь точных байтов по описанной цепочке. Она не проверяет истинность математических утверждений, корректность доказательств или смысл исторических статусов внутри архива. Внутренние отчёты и вложенные manifests рассматриваются как архивные байты, а не независимые удостоверения.

Исторические Git IDs используют SHA-1, у которого известны криптографические ограничения устойчивости к коллизиям. Связь через Git tree и manifest зависит от этих свойств SHA-1. Дополнительные SHA-256 закрепляют точные опубликованные копии и исследовательский ZIP, но не заменяют SHA-1 в исторической Git-цепочке.

Автономный verifier дополнительно проверен отрицательными тестами и запуском с Python `-O`; подпись отдельно сверена через GnuPG. Эти проверки относятся к целостности и подписи, а не к математике.
